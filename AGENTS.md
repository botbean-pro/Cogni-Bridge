# Repository Guidelines

## Project Structure & Module Organization

CogniBridge is a React 18 single-page learning app built with Vite. `src/` contains the app entry points, shared styles, translations, and UI components. Student screens and reusable student UI live under `src/components/student/`; Cogni-Flow chat pieces are in `src/components/student/flow/`. Mentor UI is under `src/components/mentor/`. Static assets belong in `src/assets/`. The Vercel serverless chat endpoint is `api/chat.js`. `dist/` is generated by the build; do not edit it directly.

## Build, Test, and Development Commands

- `npm install` installs the dependencies in `package-lock.json`.
- `npx vercel dev` runs the app and local Vercel functions, including `/api/chat`.
- `npm run dev` runs Vite alone; API routes are not available in this mode.
- `npm run build` creates the production bundle in `dist/`.
- `npm run preview` serves the built bundle locally for a visual check.

## Coding Style & Naming Conventions

Use the existing JavaScript/JSX and CSS conventions: two-space indentation, semicolons, single-quoted JavaScript strings, and clear component boundaries. Name React components and component files in PascalCase (for example, `StudentPage.jsx`); use camelCase for utilities and hooks, and descriptive kebab-free names for CSS files (for example, `flow.css`). Keep student and mentor features in their respective folders, and reuse shared styles or translations where appropriate. No formatter or linter is configured, so follow nearby code.

## Testing Guidelines

There is no automated test script or test framework configured in `package.json`. For UI changes, run `npm run build` and inspect the affected screen with `npx vercel dev` (especially when changing API behavior). Do not add tests that require external credentials; document any manual verification steps in the pull request.

## Security & Configuration

Copy `.env.example` to `.env.local` for local secrets and configuration. Set `OPENROUTER_API_KEY` and `OPENROUTER_MODEL` there; never expose secrets through `VITE_` variables or commit `.env.local`. Vercel deployment variables are configured in project settings. Treat browser local storage and demo authentication as prototype-only, not as secure storage for real student records.

## Commits & Pull Requests

Recent history uses short, informal summaries rather than a strict commit format. Write a concise imperative commit subject that describes the change. Pull requests should explain the user-visible change, list relevant verification, link an issue when applicable, and include screenshots for visual changes. Call out environment-variable or deployment changes explicitly.
